# FA: финансовый агрегатор (этап 1, фронтенд-прототип на моках)

Общие инструкции для ИИ-агентов (Cursor, Claude Code, Codex). Единственный источник: правки вносить сюда. `CLAUDE.md` подключает этот файл.

Монорепо pnpm: `apps/web` (Next.js App Router, TypeScript strict), `packages/contracts` (zod-схемы, `DataGateway`), `packages/engine` (чистые расчёты), `packages/fixtures` (детерминированные моки).
Спека этапа 1: `specs/Finance Aggregator Spec.md`. Читать по необходимости, целиком не загружать. План текущего эпика: `docs/plan-e5.md`.

## Команды
- `pnpm dev`: приложение (`NEXT_PUBLIC_DATA_SOURCE=mock`)
- Гейты: `pnpm format:check`, `pnpm typecheck`, `pnpm lint`, `pnpm lint:canaries`, `pnpm depcruise`, `pnpm knip`, `pnpm test`, `pnpm golden:check`, `pnpm build`, `pnpm bundle:report`, `pnpm e2e`
- Один тестовый файл: `pnpm vitest run <path>` из корня (не `pnpm --filter … exec vitest`: там нет алиаса `@/`).
- Перед каждым коммитом запускай навык `/verify`.
- Правила агентов по путям: источник `.claude/rules/*.md`, копии для Cursor `.cursor/rules/*.mdc` генерирует `pnpm rules:sync`, сверяет `pnpm rules:check`.

## Язык
- Со мной общайся по-русски.
- Код, идентификаторы, комментарии и сообщения коммитов на английском (Conventional Commits). Тексты интерфейса на английском.

## Нерушимые инварианты
1. Деньги это `Cents` (целые центы), ставки это `Rate` (десятичная строка). Никакого float: ни `toFixed`, ни `parseFloat`, ни умножения денег на `number`. Арифметика через `@fa/engine` и decimal.js, округление half-up один раз на выходе.
2. Профиль пользователя живёт только в браузере. Ни один сетевой запрос, параметр gateway, лог или аналитика не содержат его полей.
3. Органическая выдача не знает о рекламе: у `Product` и `Institution` нет коммерческих полей, `SponsoredSlot` монтируется только в `apps/web/src/app/**`.
4. У каждого показанного факта есть источник (`Fact<T>`, `Provenance`). Моки помечены `isMock: true`, баннер DEMO DATA на каждой странице.
5. Расчёты детерминированы: время через `asOf` или `shared/lib/clock`, случайность только через seed.
6. Налоговые, страховые и рыночные значения не придумывать. Нет проверенного источника: помечай `unverified` и спроси меня.

## Архитектура (кратко, подробности в правилах по путям)
- Слои `app → widgets → features → entities → shared`. Импорт только вниз. Слайсы одного слоя друг друга не импортируют. Доступ к слайсу только через публичный API (`index.ts`, у `entities` ещё `queries.ts`).
- `getGateway()` только в `entities/*/api`. `fetch` только в `shared/api/http.ts`. `localStorage` только в `entities/profile/model/persist.ts`, плюс inline-скрипт в корневом layout, который смотрит лишь наличие ключа `fa.profile` (ADR-017). Запись профиля только в `features/edit-profile`.
- Данные страниц загружаются при сборке (`'use cache'`) и приходят виджетам пропсами; клиент при первой загрузке не обращается к gateway и не получает zod (ADR-016).
- `page.tsx` тонкая композиция, не длиннее 80 строк.

## Как работать
- Сначала ищи готовое решение (реестр компонентов `docs/component-registry.md`, спека раздел 6), потом пиши новое.
- Небольшими шагами. После каждого шага проходят `pnpm typecheck` и релевантные тесты.
- Новая зависимость, новое правило линтера, смена слоя или границы: только с моего явного согласия и ADR (`/add-adr`). Предложение ревьюера не означает согласия.
- Новая функция `engine` идёт с «золотым» кейсом (`/add-golden-case`). Ожидаемые значения считаются независимо и не копируются из вывода `engine`. Если менялся `engine`, перед коммитом проходит `pnpm golden:check`.
- Правила линтера не ослаблять и не отключать, чтобы пройти проверку. Исправляй причину. Исключение: `eslint-disable-next-line <rule> -- <причина не короче 10 символов>, <ссылка на задачу>`.
- Не использовать `--no-verify`. Lock-файлы и сгенерированные файлы руками не править. Не коммитить с красными гейтами.
- Юридические и продуктовые тексты (приватность, раскрытие, страхование) пишутся черновиком с пометкой DRAFT и утверждаются мной.
- Вне объёма этапа 1: реальные данные, backend, карты, ипотека, брокеры, аналитика. Не добавлять без запроса.

## Навыки
- Проектные (`.claude/skills/`, вызываются явно): `/verify`, `/new-slice`, `/add-adr`, `/add-golden-case`, `/add-lint-canary`, `/add-product-category`.
- Общие инженерные (`.agents/skills/`, установлены через `skills-lock.json`): применяются по описанию. При конфликте с этим файлом или правилами по путям прав этот файл.
