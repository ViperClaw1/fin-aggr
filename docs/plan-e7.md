## Шаг 1. Lighthouse CI, только отчёт (0,5 дня)

В работе.

- Против `pnpm --filter @fa/web start` после `pnpm build`. 5 прогонов, в зачёт медиана, мобильный профиль Lighthouse (пресет по умолчанию, не `desktop`).
- Маршруты: `/`, `/compare/cd`, `/product/prod_cd_0001`, `/banks`. Идентификатор продукта — первый CD генератора, от seed не зависит.
- Два сценария: без профиля и с полным черновиком (тот же конверт, что в `compare-cls.spec.ts`). Скрипт кладёт его в `localStorage` до прогона. Для сценария с профилем `disableStorageReset`, иначе Lighthouse сотрёт ключ; кэш HTTP после этого визита скрипт чистит, чтобы прогон не был тёплым.
- Пороги предупреждениями, job не падает из-за оценки: Performance ≥ 85 только на `/compare/cd`; TBT ≤ 300 мс и CLS ≤ 0,1 там же.
- Приёмка без профиля: медиана трёх PSI 2026-11-02, мобильный, Performance 100 (прогоны 100, 99, 100), TBT 70 мс, LCP 1.0 с. С профилем — раннер `41662400511` (ADR-016): Performance и CLS прошли, TBT 441,5 мс. В CI Performance и CLS — `error`, TBT — `warn`. Ноутбук и Brave в зачёт не идут.
- Меню Compare: наведение на десктопе, клик на узком экране, без зазора 4 px (`md:top-full`). e2e в `p0.spec.ts`.
- После деплоя на `main` джоба `production-commit` сверяет `<meta name="build">` (`VERCEL_GIT_COMMIT_SHA`) с `github.sha`.

- Firefox падает, если второй контекст выключает JavaScript.
- WebKit не открывает меню Compare по наведению: `(hover: hover) and (pointer: fine)` в этом браузере Playwright не совпадает.

`upgrade-insecure-requests` убран из CSP (ADR-015): WebKit поднимал скрипты `http://localhost` на https, страница не гидрировалась. Vercel и так отдаёт только HTTPS.
