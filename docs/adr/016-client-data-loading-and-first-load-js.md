# ADR-016: Client data loading and First Load JS

- Status: accepted
- Date: 2026-10-28 (accepted 2026-10-28 with D1 and D7)
- Relates to: ADR-005 (gateway), ADR-008 (rendering), ADR-013 (money in contracts), ADR-015 (CSP)

## Context
AC-8: First Load JS of `/compare/cd` (60 CDs of a 120-product data set) at most 200 KB gzip without the PDF module. React and Next alone take about 150 KB. A zod chunk (about 34 KB gzip) is on every route today.

Measured with `pnpm bundle:report` (Next's `route-bundle-stats.json`, gzip of each first-load chunk), 2026-10-28, before any change:

| Route | First Load JS, KB gzip |
| --- | --- |
| `/` | 179.0 |
| `/_not-found` | 179.0 |
| `/dev/components` (404 in production) | 188.1 |

How zod reaches the client, established by reading the code; to be confirmed in `next analyze` and recorded here with each commit:
- (a) `money/parse.ts` imports the `Cents` and `Rate` schemas as values, so any `parseCents` or `parseRate` in UI code pulls zod. Inputs in the profile drawer will sit in the layout, so on every page.
- (b) `@fa/contracts` declares no `sideEffects`, and `primitives.ts` runs `z.config({ jitless: true })` (ADR-015), a real side effect.
- (c) The profile store parses `ProfileDraft` in the root providers (`HydrateProfile`).
- (d) `getGateway()` imports `createMockGateway` statically; the mock checks every response with the schemas. Not on any route yet; it will be with the first client query in E5.

Fixtures: every `retrievedAt` is `2026-10-01T00:00:00Z`, later than `AS_OF = 2026-09-30`, and the UI counts freshness from the wall clock, so the demo text depends on the build date (invariant 5).

## Decision
- **D1. The catalog loads on the server at build time** (extends ADR-008). `/compare/[category]` and `/product/[id]` load their data in a server component, inside a `'use cache'` function so the result joins the static shell (Next 16.4 Cache Components), and pass it to the widget **as props** (revised 2026-10-29, was `dehydrate` + `HydrationBoundary`, see below). The data must be serializable: plain objects, no class instances. The client never calls the gateway for page data; filters run in memory (`filterProducts`). On the server and at build time the mock always runs with `failureRate: 0` (like `latency: 'none'`), whatever `NEXT_PUBLIC_MOCK_FAILURE_RATE` says, so a build never fails at random. Test: `getGateway()` in server mode ignores the failure rate.
- **D2. The gateway loads lazily.** `getGateway()` returns a thin object at once; each method awaits `import('./gateway.mock')` or `import('./gateway.http')` and calls it. Both still check responses with the schemas. A failed `import()` becomes `GatewayError('unavailable', …, true)`, so the existing retry policy applies. The wrapper caches the load promise only on success (`shared/lib/lazy-once.ts`, shared with D5): a rejected promise is dropped, otherwise every retry would get the same error. The wrapper is an object literal typed `DataGateway`, so a new method does not compile until it is forwarded. depcruise `gateway-impl-dynamic-only`: outside tests, `gateway.mock` and `gateway.http` are reached only through `import()`. Tests: the first load fails, the retry succeeds; every method is forwarded; the contract suite runs through the wrapper. The `DataGateway` type and the ESLint GATEWAY rule do not change.
- **D3. No zod at runtime in client and engine code** (ADR-013 amendment). Zod-free checks (`contracts/src/checks.ts`, `money/checks.ts`: `isRate`, `asSignedRate`, `asIsoDate`, `isId`, `RATE_ZERO`, …) share their patterns with the schemas through `patterns.ts`, and a test keeps both in agreement on generated samples. `money/parse.ts`, `engine/src/money.ts`, `shared/lib/clock.ts` and both `search-params.ts` use the checks; schemas are imported as types only, so no renames. ESLint `NO_SCHEMA_CALL` bans `.parse(`/`.safeParse(` on capitalised identifiers except `Date` and `JSON` in `packages/engine/src` and `apps/web/src/{features,widgets,entities,shared/ui,shared/lib}` (tests, `shared/api`, the stand exempt), with canaries. depcruise rule: `money/{parse,format,compare,errors}.ts` never import `zod` or the schema modules as values. The rule sets `dependencyTypesNot: ['type-only']`, so `import type { Cents }` stays allowed. Two canaries: a value import of the schema fails, an `import type` passes.
- **D4. Declare side effects.** `packages/contracts/package.json`: `"sideEffects": ["./src/primitives.ts"]`. Every schema module imports `primitives.ts`, so the zod setting is kept. Check: the AC-4 e2e "page loads without CSP violations". `@fa/contracts` is consumed as source (`exports: ./src/index.ts`, `transpilePackages`); whether Turbopack honours `sideEffects` there is unknown, only the measurement tells. If the numbers do not move, record that here and treat D3 as the main path.
- **D5. Lazy profile schema.** `entities/profile/model/schema.ts` is the slice's only zod user and is reached through `import()` (`load-schema.ts`, caches only a successful load). The store's storage loads it before the first read and drops writes until then, so a failed load hydrates an empty draft with `loadError` and never overwrites the stored profile; edits before hydration are rejected. `parseImport` is async and reports a failed load as `unavailable`. Completeness (`toCompleteProfile`, every render) uses the zod-free `isProfile`, built on constants shared with the schema (`profile-rules.ts`) and kept in agreement by a test. Node tests cover a valid draft, broken JSON, an old version, an oversized import and a failed `import()`.
- **D6. `now` for mock data comes from the data set.** Additive `getDatasetInfo(): Promise<{ asOf: IsoDate; isMock: boolean }>` on `DataGateway` (REST `GET /v1/meta`), useful for a real backend too. Mock mode counts freshness from `asOf`; http mode from `shared/lib/clock`. Fixtures spread `retrievedAt` by seed, per kind of fact, never after `AS_OF`: APY 0–14 days back, terms 0–150 days, bank metrics from their report `asOf`. A fixture test checks that each kind has both fresh and stale examples for `STALE_AFTER_DAYS`. Done: retrieval offsets come from their own seeded stream (`seed ^ 0x5eed`), so no other value moves; bank metrics take a quarter-end report date (2026-09-30, -06-30, -03-31) and are retrieved on it. `freshnessNow(datasetInfo)` (`entities/fact`) takes the mode from the answer's `isMock`, not from env; pages load `datasetInfoQuery` with their data (D1). The planned `useFreshnessNow()` hook was dropped with the D1 revision: no client query needs it. The contract suite checks that nothing served was retrieved after `asOf`. A failed gateway load keeps its reason in `GatewayError.cause`.
- **D7. Budget as a CI gate.** `tools/bundle-budget.mjs` reports per route (CI step after `build`) and fails above 200 KB gzip on `/compare/[category]`, when that route is missing from the build, or when zod (`$ZodType`) is in the first load of any route but `/dev/components`.

D1 details. The first version hydrated TanStack (`dehydrate` + `HydrationBoundary`, client `staleTime: Infinity`). Its static HTML held only a skeleton: the URL filters (nuqs) suspend while prerendering, and rendering the table in the fallback is impossible with `useQuery`, which reads `Date.now()` during render, an error in a Next 16 prerender outside `<Suspense>`. Revised (decision 2026-10-29): `loadCompareData(category)` in `'use cache'` returns products, the institution fields the table reads, and `datasetInfo`; the widget renders the same table as the `<Suspense>` fallback without URL filters, so the HTML holds the whole catalog with freshness text, and URL filters apply after hydration (with a filter in the URL the full list shows until then). A failed load fails the build instead of shipping an empty page. Data freshness is the build's; rebuilding refreshes it. An unknown category renders the not-found page with `noindex`; with partial prerendering the status stays 200. `dynamicParams = false` is not an option: with `cacheComponents` exporting it fails the build, and Next recommends `notFound()` instead (Next 16.4.3 docs, `migrating-to-cache-components.md`, "`dynamicParams` is not supported").

Query keys: `normalizeProductQuery` / `normalizeInstitutionQuery` (`query-keys.ts`) apply the same default constants as the schemas, so a server prefetch (D1) and a client query build equal keys; `FactQuery` has no defaults and its request is the key. A test checks normalizer output against `parse`.

depcruise: until 2026-10-28 every npm rule (`contracts-depend-on-zod-only`, spec §7.3) checked nothing: `node_modules` sat in `exclude`, which drops npm edges from the graph. AC-10 did not catch it because that rule had no canary. Fixed by keeping `node_modules` only in `doNotFollow`; the canary `contracts/src/canary/npm-not-zod.canary.ts` now guards it.

## Alternatives considered
- Split `Cents` into `CentsSchema` and a type: about 100 `Cents.parse` / `Rate.parse` call sites and dozens of schema compositions to rename for the same runtime result as D3.
- A mock-only `asOf` constant in `shared/api`: simpler, but the mock and a real backend would differ.
- `zod/mini` for client schemas: changes every schema; next step only if D1–D5 are not enough.
- One `retrievedAt` window of 45 days: no stale terms or bank metrics in the demo.

## Consequences
- Commit order, each with `pnpm bundle:report` before and after recorded here: report script (this ADR) → D4 → D3 → D5 → D2 → D6 → D1 (with compare-table), then D7 and status `accepted`.
- New e2e after D1: on `/compare/cd` the first load requests no mock or fixture chunk, and the data is in the HTML.
- If the numbers after D1–D5 still exceed the budget, AC-8 itself is revisited rather than cutting features silently.
