## Принципы этапа 2

1. **Профиль пользователя на сервер не попадает** (ADR-004). Сбор работает только с публичными сведениями о банках.
2. **Браузер не ходит в Supabase.** Чтение только на сервере в загрузчиках `'use cache'`. CSP (`connect-src 'self'`) и бюджет первой загрузки (AC-8) не меняются.
3. **`DataGateway` не меняется.** Supabase — третья реализация рядом с `mock` и `http`. У `DatasetInfo` в шаге 3 добавляется `domains` (ADR-019).
4. **Схемы `@fa/contracts` — единый источник правил** на сборе и на чтении.
5. **Деньги и ставки без float** (ADR-003, ADR-013). Ставки строкой, деньги целыми центами. Метрики банков в контракте `number` — исключение, как и сейчас.
6. **У каждого факта источник** (`Provenance`). Государственные API: `verified`, `by: official_api`. Скрейпинг: `unverified` до проверки человеком, затем `verified`, `by: human`.
7. **Не выдумывать значения** (инвариант 6). Нет проверенного источника — `unverified` и задача человеку.
8. **Фикстуры и мок остаются** для тестов, стенда и локальной разработки.
9. **AC-8 держится на реальных данных.** Каталог на моках — 60 CD. Реальный может быть в разы больше; производительность `/compare` проверяется на реальном объёме (шаг 9).

## Шаг 5. Расписание (0,5 недели, вместе с шагом 4)

Сделано 2026-11-07. GitHub Actions `schedule`, отдельный workflow на частоту, `concurrency` по источнику (`ingest-<id>`, без отмены текущего запуска), `timeout-minutes`, один повтор при сетевой ошибке в `packages/ingest` (`onceOnNetworkError`). Репозиторий публичный, минуты стандартных раннеров не ограничивают.

Источник без флага `ready` по-прежнему пишет `source <id> pending` и выходит с кодом 0. `fdic-institutions` с 2026-11-11 помечен `ready`: нет зарегистрированной задачи — запуск падает. Секреты базы проверяются только для готовых источников.

Минуты — 17, 37 или 47: GitHub теряет и задерживает cron на минуте 0. С `f9c48b8` ни один запланированный `bank-rates` не стартовал, стартовали только ручные. 2026-11-17 к 08:48 UTC не стартовали контракт базы, возраст очереди, дневные правила, проверка формы и дневной 07:00. Контракт базы — `37 3 * * *`, возраст очереди — `17 4 * * *`, проверка формы — `37 6 * * *`, браузеры — `47 22 * * *`. Банки идут в :17 и :47 с 04 до 12 UTC: часы выводятся из ночных окон активных банков (`overnightUtcHours`, ADR-020), старые слоты 03–10 открывались до окна. Повтор в ту же ночь не делает второй запрос. `amex-cd-page` — в конце той же джобы, один запрос на неделю UTC, внутри ночного окна Денвера.

С 2026-11-18 основной триггер — `pg_cron` и `pg_net` в Supabase: `workflow_dispatch` на каждый workflow, `bank-rates` через `dispatch_bank_rates` только при открытом окне, остальные через 12 минут после своего GitHub cron. `schedule` GitHub остаётся запасным, дубль безвреден. Ответы GitHub — в `dispatch_log`, ночной watchdog `bank_rates_watchdog()` открывает issue `scheduler: missed window`. Подробности — ADR-020 «Scheduler», проверка — `docs/runbooks/scheduler.md`.

| каждый день 07:17 | `17 7 * * *` | `ingest-daily-0700.yml` | `fdic-institutions`; `treasurydirect` (with the Fiscal Data cross-check) |

Ручной запуск `bank-rates` не получает вход, который отключает окно: окно — правило ADR-020. Запуск попадает в окно, только пока местный час банка 22, 23 или 0–5. По UTC, с 22:00 местного до 06:00 (06:00 уже вне окна): зимой восток 03:00–11:00, центр 04:00–12:00, горы 05:00–13:00, Тихий океан 06:00–14:00, Аляска 07:00–15:00, Гавайи 08:00–16:00. Летом каждый промежуток на час раньше, кроме Гавайев и Аризоны (Аризона весь год 05:00–13:00). Пилотные банки в `America/Denver`: зимой 05:00–13:00 UTC, летом 04:00–12:00 UTC. Вне окна и при повторе в ту же ночь лог — `source <id> held reason=outside_window` или `reason=already_fetched`, и строка в `job_runs` пишется всё равно.

## Шаг 8. Ставки банков: пилот и фабрика подключения (ADR-026)

Решение владельца 2026-11-26: при 3–5 банках продукт ценности не несёт. Порог запуска — 50 ключевых банков, дальше темп в несколько сотен организаций в месяц. Покрытие меряется долей депозитов рынка и доступностью по штатам, а не числом организаций (ADR-026). Рынок — около 8–8,5 тыс. организаций: 4 238 банков FDIC на конец Q2 2026 и около 4 тыс. кредитных союзов. Шаги 8.1–8.3 — сделанный пилот; 8.4–8.10 — фабрика.

### 8.1 Правила в коде (сделано 2026-11-11)

Единственный выход в сеть за страницей банка — `createScrapeSession`: только https без входа и без логина, `robots.txt` этого хоста перед страницей, пауза 10 с на регистрируемый домен (Crawl-delay не подменяет её), окно 22:00–06:00 в часовом поясе банка, `If-None-Match` и `If-Modified-Since`. User-Agent: `FA (+https://fin-aggr.vercel.app; <ящик>)`, ящик из `FA_SCRAPE_MAILBOX`. Капча, 401/403/429 и запрет robots — ручной режим (`source <id> manual <reason>`, `sources.status = manual`). Нагрузка — `load <domain> requests=N bytes=N` и `job_runs`. Исключение банка: `pnpm ingest:exclude <bank-id> --requested <iso>`, срок 24 часа. Цитата факта короче 400 символов, снимки только в приватный бакет `raw`. Банк, у которого в текущем окне уже есть `job_runs` с `request_count > 0`, пропускается (`held reason=already_fetched`). Входа, который отключает окно, нет. ADR-026 меняет одно: параллельно по разным доменам (8.8) и воркер со статическим IP для заблокированных; правила выше остаются на каждом запросе.

### 8.2 Реестр (сделано 2026-11-12)

`selectBankRegistry` и `upsertBankSources`, источник `bank:<id учреждения>`, `operational_kind = scrape`. Исключённый или ручной ряд не перезаписывается. ADR-026 меняет порядок когорт: сначала национальные онлайн-банки, затем крупнейшие по депозитам до нужной доли рынка, затем крупнейшие в каждом штате, кредитные союзы с открытым членством — по явному списку.

### 8.3 Пилот: три адаптера (сделано 2026-11-15 — 2026-11-25)

Ally Bank `fdic:57803` (savings), American Express National Bank `fdic:27471` (JSON, CD и savings), Sallie Mae Bank `fdic:58177` (HTML-таблица CD). Домен `bank_products`. Первое подключение — в очередь; после подтверждения публикуются чистые строки. 2026-11-25: одобрение оставляет только id из снимка (`publishApprovedBankRows`), правило `duplicate_term`, демо-фикстуры скрываются в категории с реальными продуктами. Vetting 2026-11-17: Bread, EverBank, Happen, CIT (savings), Barclays (savings) — «take»; Synchrony, Capital One, ACCESSbank — позже; Marcus, Live Oak — блок. Эти восемь идут первыми через фабрику, не отдельным кодом.

### 8.4 Замер рынка (1,5 недели)

Чтение без публикации по 500 крупнейшим организациям по депозитам через `createScrapeSession`, в рамках правил 8.1. По каждой: найдена ли страница ставок, есть ли ставки без JavaScript, блокировка (капча, 401/403/429, robots), отпечаток платформы сайта или rate-виджета, есть ли PDF Truth in Savings. Таблица `survey_results`.

Код 2026-11-26: `packages/ingest/src/survey/`, миграция `20261126120000_survey_results.sql`, `pnpm ingest:survey run [--limit N]` и `pnpm ingest:survey report`, workflow `ingest-survey.yml` (вручную и в 06:37 и 09:37 UTC). Главная страница и лучшая ссылка на ставки того же сайта, не больше двух запросов на организацию сверх `robots.txt`. Блок пишется в строку замера и не меняет `sources`. Банк вне окна откладывается до следующего запуска; обойдённые пропускаются. 8 очередей по сайтам параллельно. Ссылка на ставки ищется только с главной, поэтому «страница не найдена» — оценка снизу. Ждёт: миграция в базе, первый прогон.

Готово, когда: кривая «N организаций → доля депозитов»; доля блокировок; кластеры платформ с числом организаций; цели 8.9 и сроки пересмотрены по этим цифрам и записаны в ADR-026.

### 8.5 Конфиг-адаптеры (1 неделя)

Адаптер — данные, не код: `json_path`, `ld_json`, `html_table`, `pdf_table`; URL; соответствие полей источника полям `Product`. Общие части (`classifyTableRow`, чтение ld+json) исполняют любой конфиг. Таблица `adapter_configs`. Sallie Mae переводится на конфиг первым; Amex остаётся кодом (JSON-эндпоинт с заголовками).

Код 2026-11-26: `scrape/banks/config.ts` (исполнитель `html_table`, срок через `classifyTableRow`), `scrape/banks/configs.ts` (список банков на конфиге). Sallie Mae на конфиге дала те же продукты, что код, на трёх вариантах страницы; код `58177.ts` удалён, регистрация и одобрение идут по `CONFIG_BANKS`. Пока конфиги лежат в репозитории; таблица `adapter_configs` появится в 8.6, когда конфиги начнёт предлагать модель. `ld_json`, `json_path`, `pdf_table` — с первым банком, которому они нужны.

Готово, когда: Sallie Mae на конфиге даёт те же продукты, что код; новый банк на известной платформе = конфиг + снимок + тест, без нового кода.

### 8.6 Подключение моделью (1,5 недели)

Discovery: от `WEBADDR` (итоговый хост после редиректов) — `robots.txt`, `sitemap.xml`, ссылки про ставки, типовые пути; модель классифицирует кандидатов. Затем модель по снимку предлагает конфиг и продукты, у каждого поля дословная цитата. Ночной прогон — только по конфигу, без модели. Модель снова — только при поломке адаптера; новый конфиг — предложение в очередь. Модель, версия и версия промпта пишутся в строку очереди. Выбор провайдера и SDK — отдельный ADR и пин версии (ADR-014).

Код 2026-11-26 (ADR-027: Anthropic SDK 1.8.0, `claude-opus-5-5`): `scrape/onboard/propose.ts` — модель по снимку предлагает конфиг `html_table` и продукты с цитатами; проверки «цитата — подстрока снимка» и «конфиг воспроизводит продукты модели». Таблица `adapter_configs` (миграция `20261126150000_adapter_configs.sql`): `proposed` → `active` при `pnpm ingest:approve` строки `adapter_proposal:<id>`, прежний активный — `retired`. `bank-rates` подхватывает активные конфиги из базы; конфиг из базы проверяется по форме и при ошибке пропускается. Запуск: `pnpm ingest:onboard <fdic:N> [url]` или workflow `ingest-onboard.yml` (URL по умолчанию — `rates_url` из замера). Discovery по `sitemap.xml` и типовым путям пока нет: URL — из замера или вручную. Минуты человека: `pnpm ingest:approve <id> --minutes N` пишет `review_queue.review_minutes` вместе с решением (миграция `20261126170000_review_minutes.sql`). Ждёт: секрет `ANTHROPIC_API_KEY`, первые банки.

Готово, когда: 8 банков из vetting подключены через конвейер; на каждый — запись времени человека.

### 8.7 Автопроверки и политика публикации (1 неделя)

Проверки ADR-026: цитата — подстрока снимка; значение разбирается из цитаты; конфиг воспроизводит продукты модели; вторая экстракция совпадает; APY согласуется со ставкой и капитализацией; совпадение с PDF, если он есть; выброс против `national_rates`; `duplicate_term`, сдвиг, давность, счётчик (ADR-020). Всё прошло — `verified`, `by: 'automated_check'` (контракт, аддитивно). Человек смотрит: проваленные проверки, первые 10 организаций каждого шаблона, 10% случайной выборки в неделю, сдвиги больше 50 б.п. Отклонённая выборка останавливает автопубликацию шаблона. На сайте у ставки видно, как она проверена (текст DRAFT).

Готово, когда: решение владельца по политике записано; тест — продукт с цитатой не из снимка не публикуется; тест — расхождение двух экстракций идёт в очередь.

### 8.8 Админка и прогон (1,5 недели, параллельно 8.6–8.7)
