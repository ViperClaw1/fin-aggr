# Cursor config for FA (Stage 1)

Cursor and Claude Code share one set of instructions. Nothing is written twice by hand.

| What | Single source | Cursor reads | Claude Code reads |
| --- | --- | --- | --- |
| Always-on instructions | `AGENTS.md` | `AGENTS.md` (always applied) | `CLAUDE.md` → `@AGENTS.md` |
| Path-scoped rules | `.claude/rules/*.md` | `.cursor/rules/*.mdc`, generated by `pnpm rules:sync` | `.claude/rules/*.md` |
| Project skills (slash commands) | `.claude/skills/*/SKILL.md` | same folder (Cursor loads `.claude/skills/` for compatibility) | same folder |
| General engineering skills | `.agents/skills/*` (`skills-lock.json`) | same folder | same folder |
| Permissions | — | `.cursor/cli.json` (Cursor CLI) | `.claude/settings.json` |
| Format on edit | `.cursor/hooks/format.mjs` | `.cursor/hooks.json`, `afterFileEdit` | `PostToolUse` hook in `.claude/settings.json` |
| Ignored by the agent | `.cursorignore` | yes | `deny Read(...)` in `.claude/settings.json` |

## Apply

1. Copy `AGENTS.md`, `CLAUDE.md`, `.cursor/`, `.cursorignore`, `tools/sync-agent-rules.mjs`, `docs/cursor-config.md`, `.env.example` into the repo root.
2. Add to the root `package.json`:
   ```json
   "rules:sync": "node tools/sync-agent-rules.mjs",
   "rules:check": "node tools/sync-agent-rules.mjs --check"
   ```
3. Add `- run: pnpm rules:check` to `.github/workflows/ci.yml` after `pnpm lint:canaries` (a new CI check: needs approval).
4. Run `pnpm rules:sync`, then `pnpm format:check`.
5. In Cursor: Settings → Rules. Each of the 4 rules must show as attached by its file pattern (not "Always" and not "Manual"). Settings → Skills: the 6 project skills and the `.agents` skills are listed.
6. Copy `.env.example` to `.env.local` (Cursor has no equivalent of the `env` block in `.claude/settings.json`).

| `.cursorignore` | `.env*` (except `.env.example`), build and test output |

## Project skills in Cursor

Type `/` in Agent chat:

| Skill | Use |
| --- | --- |
| `/verify` | All gates in order, pass/fail table. Before every commit |
| `/new-slice <layer> <name>` | FSD slice with public API |
| `/add-adr <title>` | Numbered ADR from the template, status `proposed` |
| `/add-golden-case <function> <scenario>` | Engine case with Python `decimal` expected values |
| `/add-lint-canary <rule>` | Canary that must fail on its rule |
| `/add-product-category <name>` | Contract → fixtures → engine → slice → table → route |

All except `verify` have `disable-model-invocation: true`: they run only when called, like slash commands. `.cursor/commands/` is not used: Cursor turns commands into skills (`/migrate-to-skills`), and these skills already exist.

`$ARGUMENTS` in the skills is Claude Code syntax. In Cursor the text typed after the command is the argument; each skill names what it expects next to `$ARGUMENTS`.

## Caveats (not checked in a live Cursor session)

- `globs:` is written as one comma-separated line. If Cursor shows a rule as "Manual", switch to the YAML list form in `tools/sync-agent-rules.mjs`.
- Hooks are beta. The command `node .cursor/hooks/format.mjs` assumes the project root as working directory; if the Hooks output panel shows "module not found", use `node hooks/format.mjs`.
- `.cursor/cli.json` applies to Cursor CLI. In the IDE, set the terminal allowlist and auto-run in Cursor Settings (per user, not in the repo).
- `.cursorignore` is best effort: a terminal command can still read an ignored file. Keep secrets out of the repo and out of `NEXT_PUBLIC_*`.
- `.agents/skills` (26 general skills) apply automatically by description. If one of them pushes against `AGENTS.md` (for example, committing or pushing on its own), `AGENTS.md` wins; remove or pin such a skill in `skills-lock.json`.
